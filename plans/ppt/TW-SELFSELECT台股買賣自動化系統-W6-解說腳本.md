## slide-2 實盤交易（2 分鐘）

先看實盤的完整流程，五個步驟。
第一步，先跑選股程式，決定要選哪些股、以及資金怎麼分配。
第二步，讓 AI 幫你產生 .env 設定檔。這裡有兩個提醒：如果是更新，請確定是否要刪除舊的實盤資料；如果更新但不刪舊資料，請確定隔天九點程式有沒有自動清倉那些決定不再持有的股票。
第三步，準備好玉山 API 憑證——p12 檔和金鑰。注意：模擬 API 的金鑰是 config.simulation.ini，實盤 API 金鑰是 config.ini；玉山規定，必須先用模擬 API 下單成功，才能申請實盤 API。另外要設定好玉山 API 的白名單。
第四步，設定雲端主機：確認靜態 IP；如果主機停機中，要先開啟；執行驗證之後，才能部署到 VM。
第五步，部署：在專案根目錄執行 ./deploy_source.sh（人工執行）——它會先跑 preflight 測試、建 image、透過 SSH 直傳到 VM、載入後重啟容器，最後比對版本指紋。注意：如果 VM 非開機時間，部署完要手動關機，否則下一個開機時間不會自行開機。

**講師提示**：五步驟總覽頁，先建立流程圖概念，之後逐頁細講。

## slide-3 再談選股：每月自動選股流程（1 分 30 秒）

再談選股——這一頁直接看目前線上每天實際在跑的「每月自動選股流程」。整條流程只有兩個交易日：每月第 1 個交易日（D1）選股、第 2 個交易日（D2）買進，由 .env 的 SELFSELECT_AUTO=1 開啟。

D1 下午 13:36 到 13:55，容器裡的主程式會叫 scripts/monthly_selfselect_run.py：先補資料（重建市值排名、把價格快取補到最近交易日；盤中會跳過補價，避免寫入還沒定案的 K 棒），再呼叫 monthly_rebalance_picker.py 選股，然後改寫 .env（先備份到 backups/），最後發 Telegram 通知。改 .env 是在容器內做的、用的就是實盤持股，所以「已持倉一律保留」這條規則不會判錯。

D1 晚上到 D2 13:25 之前，你都可以插手：對名單有意見，用 --exclude 做宣告式剔除；不要手改 .env 的名單——因為重跑時程式會依選股結果重算，手動改的內容會被蓋掉。

D2 早上 08:05 到 08:39 還有一次補跑：如果 D1 剛好 VM 關機、逾時或失敗，程式會在這個時窗補做。為什麼要趕在 08:40 之前？因為 .env 的生效點是每天 08:40 的熱重載，補跑寫入後才來得及在 D2 生效。同一時窗內最多重試三次。

D2 13:25 到 13:30，immediate 模式用收盤前窗口買進新名單，滿倉不重複買。

選股本身有四道濾網：第一，誠實候選池——用歷史股本乘當季股價還原「當時的市值前一百」，避免倖存者偏差；第二，法人確認——近 15 日法人合計買超才算數；第三，過熱剔除——離 52 週高點太近、今年漲太多、本益比太高，任兩項命中就剔除；第四，總數上限 N——只補「N 減掉已持倉」的檔數，預設 5 檔，每檔資金是腿額度除以 N。

安全帶：預設 dry-run，--apply 才寫檔並自動備份；程式絕對不會刪掉已持倉的股票——否則下一個交易日開盤的孤兒清倉會把它賣掉；keep_wait 條目視為人工管理，不增不刪；基準日若是舊的，會拒絕寫入。

**講師提示**：這頁是「每月作業」的總覽，講清楚兩件事：①時間點（D1 選、D2 買、D2 早上補跑）②四道濾網。可強調「人只要在 D2 前看過名單就好」，其他都自動。

## slide-4 潛力股掃瞄（1 分 30 秒）

先講「潛力股掃描」現在的定位：它是**參考用**，不是自動選股。舊的 find_catalyst_stocks.py 已經移除，評分邏輯留在選股程式庫的 catalyst_score()，用近 130 個交易日、前後各 65 天算四個分數：盤整品質、突破力道、量能確認、動能延續；但實盤每月選股的 catalyst_weight 預設是 0，所以這些分數不會影響買賣。
那要怎麼用？看到適合的潛力股，就自己用 keep_wait 進場：在 .env 加一條 PC_<代號>，strategy 填 keep_wait，設定進場上限價 max_entry_price、初始股數 initial_shares，再加碼幅度與停利層級。keep_wait 是「低接＋加碼＋分層停利」的手動管理型策略，價格到才買、漲到才賣。
有個好處：每月選股程式**不增不刪 keep_wait 條目**，所以手動加的持股不會被自動汰換；要移除也得自己刪，才不會被孤兒清倉影響。
最後提醒：催化劑分數高只代表「有潛力」，不是買進訊號，還是要看基本面與風險。

**講師提示**：把「掃描＝參考、進場＝keep_wait 手動」講成兩段式流程；並提醒 keep_wait 條目不受每月換股影響。

## slide-6 選股引擎：每月一次（1 分 30 秒）

這一頁講「選股引擎」現在長什麼樣子，重點放在 **N 怎麼設**。入口是 scripts/monthly_rebalance_picker.py，每個月由 monthly_selfselect_run.py 呼叫。
它有兩種風險組：normal 是布林、均線、VWAP、突破；high_profit 只留均線和突破（高風險池；名稱不代表報酬較高，改名原因見第 8 頁）。評分用 score_stock()：動能權重最重（2.0，看 21 日漲幅），技術面看離 MA20、MA60 的正偏離，穩定度看波動，催化劑權重 0（實盤不啟用）。
候選池是誠實池：--pool-n 決定「從幾檔裡挑」，預設 100；本專案的 .env 目前設 SELFSELECT_POOL_N=50。挑完再過三道濾網：法人確認（近 15 日買超）、過熱剔除（離 52 週高 7%、YTD 100%、本益比 45，命中兩項就剔除）、總數上限。
**N 怎麼設**：N 是「持股檔數」，設定在 .env 的 SELFSELECT_TOP_N，預設 5。程式把過濾後的候選依評分排序，只買最強的 N 檔；每檔資金是 SELFSELECT_LEG_PCT ÷ N（預設 100 ÷ 5 ＝ 每檔 20%）。所以想改成 3 檔，就把 SELFSELECT_TOP_N 設 3，每檔自動變 33.3%；資金級距的建議檔數在後面第 19 頁有表。
這裡最容易搞混的是兩個 N：--pool-n 是候選池大小（從幾檔挑），SELFSELECT_TOP_N 是持股數（留幾檔）。S7、S8 表格裡的 N＝50 是「候選池」，持股數一直都固定 top 5。
輸出會印出賣出／維持／買入、每檔 fixed／auto 策略、可貼進 .env 的 PC_ 設定，並寫 logs/monthly_pick.json。

**講師提示**：把兩個 N 分清楚：池大小（--pool-n）vs 持股數（SELFSELECT_TOP_N）；並用「N=3 → alloc 33.3%」當例子。

## slide-7 選股-動能,候選人前N名（1 分 30 秒）

選股池大小 N 的比較，用現行快取重跑：正常組、2022-2025、五十萬、每月換股、含手續費與證交稅。
N 等於五十：終值七十九萬五、總報酬正五十九點一趴，2022 負二十點五七趴，最大回撤負二十九點二趴。
N 等於一百：終值六十二萬二、正二十四點四趴，回撤負四十七趴。
N 等於一百五十：終值六十七萬一、正三十四點二趴，2022 跌最多。
但同一段期間，0050 買進持有是正九十九點八五趴——三個 N 全部輸給它。
這裡有一個必須講清楚的數字：**五十萬是名目本金，不是全額投入**。實測平均資金利用率只有七成多（七十二到七十九趴），實際平均只動用三十三到四十二萬，尖峰才滿倉；0050 則是買了就一直 100% 曝險。所以表面上策略輸給 0050，但策略的錢沒有全用上——每單位投入資金的報酬其實比表面數字好，只是現金沒用掉就是機會成本。這也是策略說明第六點五節的硬規則：報酬一定要附資金利用率。
要重跑的人：回測指令是 POOL_N=50 python scripts/backtest_plan2_monthly_3group.py；實盤每月選股用 scripts/monthly_rebalance_picker.py --pool-n 50。

**講師提示**：先講「三個 N 都輸 0050」，再補「但利用率只有七成多」這個口徑，兩個都要講，才是誠實的比較。

## slide-8 選股-正常組與高風險組（1 分 30 秒）

現行兩個風險組的年度比較（都是 N=50、2022-2025、五十萬、每月換股）。
正常組：總報酬正五十九點一趴；2022 負二十點五七、2023 正三十四點六一、2024 正七點七、2025 正四十點六。
高風險組（代號 high_profit）：總報酬正二十五點一趴；2022 負二十一點五三、2023 正四十六點六六、2024 負四點五九、2025 正十六點三一。
先講名稱：以前叫「高獲利組」，但 2022-2025 的實際報酬比正常組少一半以上，叫高獲利名實不符，所以改叫「高風險組」——它只留均線和突破兩支順勢策略，波動比較大，不代表報酬比較高。
結論：高風險組在 AI 爆發年（2023）衝得更高，但 2024、2025 都落後，四年總報酬只有正常組的四成多；而且兩組都沒有贏過同一段期間的 0050 買進持有（正九十九點八五趴）。
口徑也要記住：兩組平均資金利用率約七成九／七成六——50 萬不是全部壓在股票上；0050 則是 100% 曝險。

**講師提示**：先解釋「高獲利」改名的原因（名實不符），再講兩組都輸 0050 與資金利用率。

## slide-9 母專案自選股回測（2022-2025）（2 分 30 秒）

很多人記得「我們的策略長期年化 20% 以上」，這一頁把數字跟方法交代清楚，而且只看「自選股」這一部分。
母專案 tw_autotrader 用 8 檔自選股（每檔綁一個策略），同一個組合，用三種選股方式跑 2022 到 2025：
第一種固定池：年初買定這 8 檔、四年都不換，正七十七點六趴、年化十五點四趴——其實輸給同期 0050。
第二種機械化：每年底檢討一次，照 Rule 0 到 3 的硬規則汰弱留強，完全不靠人判斷，正一百九十五點五趴、年化三十一點一趴。
第三種手工、也就是人工檢討：一樣每年檢討，但換不換由人看市場資訊決定，正一百五十七點二趴、年化二十六點六趴。母專案自己的評語是：機械式報酬最高，但換股偏積極；人工版比較穩健。
定期定額每月兩萬、四年九十六萬：固定池只有正三十九點七趴，機械化逐年檢討可以到正一百二十六趴。
那跟我們現在的每月自選股差在哪？看下面這張表：
選股來源：母專案是人工先挑好的 8 檔；我們是每月用「當時市值前 50 大」的誠實池，靠評分取最強 5 檔，沒有人為挑選。
換股頻率：母專案一年一次；我們一個月一次，D1 選股、D2 換股。
怎麼決定：母專案是 Rule 0 到 3 的硬規則；我們是動能二點零、技術面零點三、穩定度零點五的評分，再加法人確認跟過熱剔除。
進場：我們是選股日收盤價就買滿。
結果：我們 2022 到 2025 是正五十九點一趴、年化十二點三，平均只動用七成九的資金、最大回撤負二十九點二趴。
但要提醒：這兩個數字不能直接比——資料源不一樣（我們是 FinMind 跟證交所，母專案是 Yahoo）、換股頻率不一樣，而且母專案腳本沒帶進本專案，重跑不出來。真正能同口徑比的只有 0050：同期含費用正九十九點九趴。
所以「年化 20% 以上」是母專案自選股加逐年汰弱留強那個版本，不是我們現在每月選股的數字。

**講師提示**：把「年化 20%+」正確歸因到「母專案自選股＋逐年檢討」；三種方式的差別是「換不換、幾年換一次、誰決定」，比較表的重點是「我們每月一次、全規則化、可重跑」。

## slide-18 風險控管（2 分鐘）

系統上線前，最後認識一下風險控管。
風險參數在 .env 檔案中設定，基本上使用預設即可：初始資金，預設五十萬；單筆交易最大風險，百分之二；每日最大可接受虧損，百分之三；每日總交易次數上限，五次；每檔股票每日交易次數上限，一次，零代表無限制。
風控功能：單筆風險限制，動態計算部位大小；每日虧損上限，達上限後停止交易；交易次數限制，避免過度交易；漲跌停過濾，跳過流動性枯竭的標的。

**講師提示**：強調「預設即可」——系統的風控設計已經過驗證，不需要自己亂調。

## slide-21 從第一次執行到每月自動（完整流程）（1 分 30 秒）

這頁是整個使用流程總覽：選股在本機跑、VM 只負責下單。
第一，部署一次：執行 deploy_source.sh，會先跑測試、建 image、SSH 直傳、載入後重啟容器並驗指紋。
第二，本機準備一次：gcloud auth login（alias VM_auth），再把 VM 的 cache 拉回本機（VM_sync_cache）。
第三，每次選股都在本機：VM_pick 先看 .env diff，確認後 VM_sync_env 寫入本機 .env 並推回 VM，容器一分鐘內熱重載；第一次還沒有任何持股，用 VM_pick_first。
第四，買進：immediate 模式下一個交易日 13:25–13:30 買滿；signal 模式等策略買訊。
第五，之後每月由 VM 上的排程自動跑（SELFSELECT_AUTO=1）。
最後用 VM_hold、performance.csv、Telegram 與對帳腳本確認。

**講師提示**：強調「本機選股、VM 下單」的分工；alias 很短，讓學員不用背長指令。

## slide-22 一檔股票的生命週期：買進（1 分 30 秒）

這頁把單一持股從買到賣講完。買進後由策略管理進出：auto 會把成交當下的策略鎖住，持有期間不換。
賣出有三個來源：策略賣訊、孤兒清倉、人工。賣掉之後名額不會馬上補，資金留現金到下一個 D1；同一檔如果還在名單裡，月中策略再出買訊仍可重新進場。

**講師提示**：搭配前一頁「賣出後不補選」一起講，學員最常誤會的就是「賣掉會自動補一檔」。

---

## slide-23 賣出後會立刻補選嗎（1 分鐘）

這一頁回答常見誤解：賣掉之後會不會馬上補一檔？不會。自選股是月頻換股，名單只在 D1 重算；賣出的空缺就留現金到下一次選股日。
兩個例外：第一，該檔如果還在名單裡，月中它的策略再出買訊可以重新進場；第二，immediate 的強制進場每檔只有第一次（logs/selfselect_filled.json），之後都靠策略訊號。
每日的「買入不足補足」只補已持有但不足的部位，空倉不會建倉，所以不會拿來補名額。

**講師提示**：強調「月頻換股＝不追高補位」是為了省交易成本；代價是資金會閒置一小段時間。
