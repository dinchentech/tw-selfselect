## slide-1 GIT上面有些甚麼（40 秒）

大家好，今天這一節不講策略、也不講程式邏輯，我們要看的是：這個專案放在 GitHub 上，到底長什麼樣子。
GitHub 就是一個「雲端放程式碼的地方」，像一個線上的資料夾，只要有網址，任何人都能開啟來看。

接下來的二十分鐘，我會一個資料夾、一個檔案地打開給你看：它負責什麼、你要改東西該去哪裡找、以及哪些東西「不會」出現在 GitHub 上——例如金鑰和憑證。

**講師提示**：先問台下有沒有用過 GitHub；沒用過也很好，今天就是把 GitHub 當成一個「看得到的資料夾」來逛。

## slide-2 Cairn（50 秒）

第一個資料夾是 .cairn，這是「專案知識層」，簡單說就是讓 AI 的記憶能跨 session。
AI 的對話每一次都是新的，前面講過什麼它不會記得；所以本專案把所有規則與進度寫成 Markdown 放在這裡：
AGENTS.md 是規則與導覽入口，cairn/LOG.md 是時間軸日誌（最新在最上面），cairn/ROADMAP.md 是路線圖，其餘是各主題的知識文件，例如部署流程、教材製作流程。
好處是：換一個對話、隔一週再回來、甚至換另一個人接手，AI 只要讀這幾份檔案就能接上。
畫面右邊就是 cairn/LOG.md，最上面那一則是 2026-11-03 的 v1.1.19：所有記帳路徑改用實際送單價。

**講師提示**：強調「AI 不會記得昨天的對話」這件事，學員才會懂為什麼要有這個資料夾。

## slide-3 Config-股票名稱,交易日（40 秒）

config 放的是設定資料，只有兩個檔案：symbols.py 是股票清單與 Yahoo Finance 的代號後綴；taiwan_holidays.json 是台股休市日曆。
這個日曆很重要：主程式每天都要判斷「今天是不是交易日」，週末、國定假日就不下單、也不發日報。
日曆每年會由 scripts/update_taiwan_holidays.py 從證交所公開資料自動更新，所以不必每年手改。
畫面上就是 taiwan_holidays.json 的內容，可以看到它是「日期清單」加上更新時間與來源。

**講師提示**：可以順帶說明：判斷交易日跟「平日」不同，過年那一整週都是平日，但不能交易。

## slide-4 core-核心程式（50 秒）

core 是整個系統的大腦，也是檔案最多的地方。挑幾個重要的講：
strategy_engine 負責把策略函式跑成訊號；risk_manager 管單筆風險、每日虧損與每日交易次數，並寫 performance.csv；market_filter 做大盤年線過濾（指數在 MA200 以下就不買）；park_asset 管「閒置資金停泊 0050」；selfselect_scheduler 是每月第 1 個交易日的自動選股排程；config_loader 負責把 .env 裡每一條 PC_ 設定解析成每檔股票的策略與資金；live_utils 是交易日曆、下單窗口與成交回報這些共用工具。
另外還有一整組選股端模組：ai_pick、candidate_pool、scoring、pit_data 等等。
想改「系統行為」幾乎都在這個資料夾，改完要記得本專案的規則：程式有改動，版號要 +1。

**講師提示**：不要逐檔念，點名三到四個最常被問的（risk_manager、market_filter、selfselect_scheduler）就好。

## slide-7 如何檢視GIT上html檔（65 秒）

這一頁是今天最實用的一招：GitHub 上的 HTML 檔不會直接顯示畫面，你點進去只會看到一堆原始碼。
解法有兩個。
第一個是最快的：在檔案頁面右上角按「Copy path」把路徑複製起來——畫面紅色箭頭指的就是那個圖示；拿到的是 github.com 開頭的網址。然後到 htmlpreview.github.com 這個網站，把網址貼上去，它就會用瀏覽器幫你把 HTML 渲染出來。
第二個是開這個專案的 GitHub Pages：本專案的交易儀表板就是這樣每天自動更新的。
記住原理：GitHub 是「放檔案」的倉庫，不是網站主機；要看網頁效果，就得用會渲染它的服務。

**講師提示**：這段建議直接現場示範一次：複製路徑 → 貼到 htmlpreview → 動畫跑起來。示範效果比講解好十倍。

## slide-8 esun_sdk-玉山sdk及API憑證(沒上git)位置（50 秒）

esun_sdk 是一個「空殼」資料夾：它的存在只是告訴程式「憑證會放在這個路徑」，但真正的憑證檔案不會上傳到 GitHub。
你會看到它幾乎是空的，因為以下這些東西全部被排除在版控之外：玉山憑證 .p12、config.ini、憑證密碼、以及 .env 這個設定檔本身。
原則只有一句話：金鑰、憑證、密碼，永遠不進 GitHub。
GitHub 上只放範本——例如 .env.example.txt 裡面全部是假值，你要自己複製成 .env 再填真的。

**講師提示**：這頁一定要講重：很多人第一次用就把金鑰推上去，公開 repo 三分鐘內就會被爬蟲掃到。

## slide-11 python_basic:gcp-setup雲主機申請（35 秒）

第二份是 GCP 雲端主機申請。
內容包括：申請 Google Cloud 免費額度、建立一台 e2-micro 的小主機（每月大約六到八美元，在免費額度內）、開啟必要 API、用 SSH 連上去。
為什麼需要雲主機？因為自動交易要「每天開盤前就在跑」，不能靠你家電腦不關機。後面部署那個章節，就是把程式送到這台主機。

**講師提示**：提醒：主機地區選台灣或鄰近區域，憑證與金鑰一樣不能上傳。

第三份就是 Python 課程本體，八週、每週一小時。

## slide-13 scripts-工具腳本（50 秒）

## slide-14 strategy-股票策略（45 秒）

strategies 是策略資料夾，四支固定策略都在這裡：布林通道反轉、VWAP 偏離、均線交叉、突破。
另外兩支不是「選股策略」而是路由與人工管理：auto_sensing 會在順勢與逆勢之間自動挑一支（買入當下鎖定），keep_wait 則是給你人工管理的低接加碼。
六支的寫法完全一樣：一個函式吃日 K 資料、吐出一欄 signal，1 是買、-1 是賣、0 是不動。
所以想改策略、或想看懂策略在做什麼，就從這個資料夾挑一支開始。

**講師提示**：可以現場打開 bollinger.py，只數行數給大家看：三十幾行而已，沒有想像中可怕。

## slide-18 Backtest.py（50 秒）

backtest.py 是回測程式，也是最安全的實驗場：改參數不怕賠錢，跑一次幾十秒就有結果。
用法是選一支策略、可選地帶參數、再用 --symbol 指定一檔股票，例如布林策略、標準差倍數二點五、只測台積電；最後會印出交易次數、勝率、總報酬，並把結果寫進 results 資料夾。
但要注意兩件事：第一，不指定股票時會回測全部標的，很慢；第二，它是簡化口徑，買進訊號只算下一根 K 的漲跌幅，不是完整持倉模擬。要看每月換股的完整投組績效，要用 scripts 裡的三組比較那支。

**講師提示**：這頁一定要講「簡化口徑」，否則學員會把這裡的勝率當成實盤績效。

## slide-19 deploy_source.sh（50 秒）

deploy_source.sh 是部署腳本，一支指令把程式送上雲主機。
它做的事：先做上線前檢查、建置映像檔、用 SSH 直接把程式送到主機，最後把舊容器停掉、換成新的 tw_selfselect_bot——它會先把母專案的舊容器停掉，因為同一個券商帳號不能兩隻機器人同時下單。
兩條規矩請記住：第一，這支腳本一律由你本人手動執行，AI 不代跑；第二，換版之後看啟動訊息或手機通知上的版號，就知道主機上跑的是哪一版。

**講師提示**：可以把「版號出現在啟動訊息、Telegram、儀表板」講一次，這是本專案刻意設計的驗證方式。

## slide-20 selfselect_trader.py主程式（60 秒）

selfselect_trader.py 是主程式，大約一千四百行，但流程其實很單純，可以想成一個時間表。
啟動時先為每檔股票抓大約一年的日 K 當暖身；接著每一分鐘看一次現在該做什麼：早上八點四十分重新載入 .env（換股名單就在這個時間點生效）、九點到下午一點半是盤中，每分鐘跑一次策略訊號，但日 K 的委託只在下午一點二十五到一點半這五分鐘送出；下午一點三十六分是每月第一天的自動選股，一點四十五分發收盤日報並產生儀表板，其餘時間就休眠等下次開盤。
有訊號之後的順序是：先檢查庫存（空手不會亂賣）、再過風控（風險、每日虧損、交易次數）、再過大盤年線、才送出委託，接著更新三本帳並發 Telegram。

**講師提示**：用「一天的時間表」講這一頁，不要逐行讀程式；學員要的是心智模型。

## slide-21 user_strategies.py預留策略（50 秒）

最後一個程式是 user_strategies.py，這是留給你自己寫策略的位置。
做法四步：寫一個函式，吃日 K 資料、回傳多一欄 signal；把函式掛進檔尾的 USER_STRATEGY_MAP；在 .env 的 PC_ 條目指定策略名稱；再把參數名稱登記到 core/config_loader.py，否則參數不會傳進你的函式。
不想從零開始也沒關係，裡面已經有四組範本可以抄：價格區間低接、週 KD 黃金交叉、自訂動能、量價策略。

**講師提示**：強調「先抄範本再改」，比叫學員從空白開始實際得多。

## slide-22 ~The End~（30 秒）

今天我們把整個專案走了一遍：從 .cairn 的專案記憶、config 與 core 的核心、data 的券商量、docs 的動畫、plans 的教材、scripts 的工具、strategies 的策略，一直到主程式、回測、部署與自訂策略。
請你記住三件事：想懂系統，看 README、使用手冊、策略說明；想調參數，先看 .env 的 PC_ 條目；金鑰與憑證永遠不進 GitHub。
剩下的，就是打開 repo 自己動手。有問題現在可以舉手，或之後把問題直接問 AI——這個專案的 .cairn 就是為了讓 AI 接得上你的進度。

**講師提示**：收尾留時間給問答；若時間不夠，至少把「三件事」再說一次。
