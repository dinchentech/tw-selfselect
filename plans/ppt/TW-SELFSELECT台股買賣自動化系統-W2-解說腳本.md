## slide-4 Python 語法的元素（1 分 30 秒）

第一個元素，資料型態。
Python 用資料型態來分類與儲存不同資料的基本格式。最常見的有四種：
整數 int，例如 10、負五；浮點數 float，例如 3.14；字串 str，就是用單引號或雙引號包覆的文字，例如 Hello；還有布林值 bool，只有 True 真、和 False 偽，兩種值。
你可以把資料型態想成不同的盒子：整數盒裝整數、字串盒裝文字、布林盒裝是或否——程式就是靠這些盒子來分類處理資料。

**講師提示**：舉生活例子：體重 70 是 int、70.5 是 float、名字是 str、「今天有沒有漲停」是 bool。

---

## slide-5 Python 語法的元素（2 分鐘）

第二個元素，變數。
變數是用來存放資料的標籤或容器。Python 是動態型別——宣告變數時不需要指定型態，直接賦值就可以了，例如 x 等於 5。命名規則上，必須以字母或底線開頭，而且區分大小寫，A 和 a 是兩個不同的變數。
第三個元素，運算子。
運算子是用來對資料進行運算與邏輯判斷的符號。算術運算子有加減乘除、整除、取餘數、次方；比較運算子有等於、不等於、大於小於這些；邏輯運算子有 and 且、or 或、not 非。

**講師提示**：可以現場互動：「3 整除 2 等於多少？餘數呢？」讓學員動腦，確認他們跟上。

---

## slide-6 Python 語法的元素（2 分鐘）

第四個元素，控制結構。
控制結構決定程式執行的流程。最重要的有兩種：條件判斷 if-elif-else，依據條件是否成立，決定執行哪一段程式碼——就像「如果收盤價大於買進價就賣出，否則繼續持有」；還有迴圈，重複執行特定程式碼——for 迴圈走訪固定範圍，while 迴圈在條件成立時持續執行。
第五個元素，內建資料結構。
資料結構是用來組織大量資料的容器。串列 List，可變動、有順序，例如一號二號加蘋果；元組 Tuple，不可變動、有順序；字典 Dictionary，是鍵值對結構，例如姓名對應 Alice、年齡對應二十五；集合 Set，無序且不重複。

**講師提示**：強調「條件判斷+迴圈」就是策略邏輯的核心——之後看 AI 寫的策略程式，90% 都在這兩種結構裡。

## slide-7 Python 語法的元素（2 分 30 秒）

第六個元素，函式。
函式是把重複使用的程式碼包裝成獨立區塊。使用 def 關鍵字定義，可以接收參數，並透過 return 回傳結果。你可以把函式想成一個「加工機器」：丟原料進去，吐出成品。

**講師提示**：建議現場示範完整流程：activate_venv → PyCharm → 開檔 → RUN。這是學員第一次實際執行程式，成功跑出結果的瞬間很重要。

## slide-15 程式的開發/執行架構（1 分 30 秒）

第三層，Docker 容器執行層。
docker compose up 啟動容器，主程式 python selfselect_trader.py 在容器內實際執行。映像由本機 deploy_source.sh 建置後直傳到 VM，容器內是程式碼的不可變副本——改 VM 上的檔案不會影響已建好的映像——但透過掛載，設定與資料跟 VM 即時連線。

這四個掛載是系統穩定運作的關鍵——容器可以隨時重建，但資料永遠留在 VM 上。

## slide-18 當程式卡死的時候（1 分 30 秒）

接下來進入本週的重點實作：程式卡死怎麼辦？
首先了解系統架構：當程式在 Docker 內卡死時，很難檢查——因為你沒辦法直接在容器裡中斷它。因此，由 Local 來執行會比較好查。
Local 跟 Docker 內最重要的差異：Docker 到玉山 API 存取資料的 IP 是靜態 IP，而且已經在玉山證券網站設定過白名單。如果你要在 Local 偵錯玉山下單 API 的程式，你一樣要把 Local 電腦的 IP 設為固定 IP，然後也必須把這個 IP 加到玉山 API 網站的白名單。
以下是使用 WSL 內 PyCharm 來偵錯的流程：先於 WSL 的 tw-selfselect 目錄中輸入 pycharm，開啟專案。

**講師提示**：本頁是偵錯課程的開場，強調「Docker 卡死難查、Local 好查」與「白名單 IP」兩個重點。

## slide-24 Debug的流程控制（2 分鐘）

這頁是 Debug 的流程控制，最核心的一頁。
第一個，Step Over，快捷鍵 F8，步過：執行目前這一行，不進入函式內部，函式一次跑完。
第二個，Step Into，快捷鍵 F7，步入：執行目前這一行，進入函式內部逐步看。
第三個，Step Out，快捷鍵 Shift 加 F8，步出：從目前函式直接跳回呼叫它的上一層。
第四個，Resume，快捷鍵 F9，繼續：恢復正常執行，直到下一個中斷點或程式結束。第五個，Stop，快捷鍵 Ctrl 加 F2，停止：終止 Debug 執行。
三個註記：第一，注意 Step Over 與 Step Into 的差異——一個不進函式、一個進函式；第二，最右邊是右斜線加紅圈，是暫時停用斷點；第三，左上方也有 Resume、Restart、Stop 可以選。

**講師提示**：本頁是偵錯操作的核心，放慢講。可以現場示範 F8 與 F7 的差異給學員看。

## slide-26 強制停止(PAUSE)（1 分鐘）

關於 PAUSE 的注意事項。
程式跑到休眠狀態時，選擇 Resume 讓程式繼續跑。左下右上 Tab 點 Console，可以發現程式順利執行到最後休眠。
這時候無法 PAUSE 暫停程式——因為已經休眠，只能 STOP 終止。所以 PAUSE 按鈕是用來暫停「正在執行中」的程式，不是暫停休眠狀態。

**講師提示**：這個細節容易誤解，強調「休眠無法 PAUSE、只能 STOP」。

## slide-27 程式卡死的處理（1 分 30 秒）

最後，整理卡死處理的完整流程。
當程式卡死時，由 AI 來查比較費時——因為 AI 無法執行 PyCharm，無法把強制執行中的程式停下來。因此，使用者可以先於 Local 的 WSL 環境，使用 PyCharm 來偵錯。
卡死停下來之後，告訴 AI 目前停下的行號，以及相關的變數值，就能很快協助 AI 找出卡死的原因。
一般來說，只要程式不卡死，AI 都能經由自己寫測試程式、修改程式、加上必要的 log 檔案，收集 AI 要判斷的資訊，就能排除程式的 bug。只有「一卡死就卡個數十分鐘」的特殊狀況，沒有使用者協助時會比較花費時間偵錯。

**講師提示**：本頁總結「人機協作偵錯」的完整分工——人提供卡點，AI 找原因。這是本週最重要的實務流程。
